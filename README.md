# AI Author Orchestration

A **harness-agnostic, repository-driven AI operating system** for planning, writing, reviewing, revising, and maintaining long-form fiction.

This is not a prompt collection. The repository teaches any capable AI harness how to collaborate on novels and novellas while preserving plot, character, world, POV, knowledge, timeline, and thread consistency.

---

## Why Repository-Driven Authoring?

Long-form fiction exceeds model context windows. Conversation history is fragile. This framework externalizes:

- **Canon** — what is permanently true
- **Planning** — what should happen
- **Narrative history** — what happened (immutable events)
- **Derived state** — current reconstructed view
- **Approvals** — hash-bound human gates
- **Manuscript** — drafts vs approved prose
- **Reviews** — structured findings

The repo is the operating system. Any harness that reads files can participate.

## Architectural Model

```text
User request
    ↓
AGENTS.md
    ↓
.ai/manifest.json
    ↓
rules dispatcher
    ↓
protocol selection (new-book vs existing-book)
    ↓
active book resolution (skip for new-book init)
    ↓
book configuration
    ↓
genre dispatcher
    ↓
skill matching
    ↓
specialist roles
    ↓
draft + reviews
    ↓
human approval (when configured)
    ↓
promote / emit events / canon proposals
    ↓
fold derived state
```

### Source Hierarchy

```text
.ai/                              How AI participants behave
.ai/examples/books/               Example-only books (not active)
books/<book>/book.yaml            What the specific book is
books/<book>/canon/               Permanent established truth
books/<book>/planning/            Intent, scene cards
books/<book>/state/initial.json   Optional bootstrap state
books/<book>/state/events/        Immutable narrative events (evt-*)
books/<book>/state/derived/       Reconstructed current state (generated)
books/<book>/approvals/           Durable human approval records
books/<book>/manuscript/drafts/   Staging prose
books/<book>/manuscript/scenes/   Approved prose
books/<book>/reviews/             Review artifacts
books/<book>/research/            Book-specific research
```

## Harness Independence

All canonical instructions live under `.ai/`. Adapters in `.ai/harnesses/` are thin pointers for Cursor, Claude Code, Codex, Gemini CLI, GitHub Copilot, and OpenCode.

**Agents are semantic roles**, not separate processes. A harness may implement `continuity-editor` via subagents or sequential role adoption—the contract is the same.

---

## Canon vs Narrative History vs Derived State

| Layer | Mutability | Purpose |
|-------|------------|---------|
| Canon | Changes only via canon workflow | Established truth |
| Planning | Revised during architecture | Intent, scene cards |
| State events | Immutable; corrections supersede | Narrative history |
| Derived state | Regenerated by fold | Current view for context |
| Manuscript drafts | Staging | Pre-approval prose |
| Approved manuscript | After approval gate | Canonical prose paths |

Approved scenes emit **state events** and optional **canon proposals**. Scene events do **not** establish permanent CANON.

---

## Event-Sourced Story State

Approved scenes emit immutable JSON events with independent IDs:

```text
books/my-book/state/events/evt-000001-scene-0047-approved.json
```

Corrections use `event_type: correction` with `supersedes[]` and full replacement deltas. Old event files are never mutated.

```bash
npm run fold -- books/my-book
npm run fold:check -- books/my-book   # read-only
```

**Principle:** `immutable narrative history + deterministic reconstruction = current story state`

---

## Approvals

When `book.yaml` → `human_approval` requires a gate, record a durable approval under `approvals/` bound to `artifact_hash`. If the artifact changes, approval is stale. Nothing canonical persists before a required gate.

---

## Genre Packs

Composable guidance packs under `.ai/genres/` — not separate frameworks. Load only matching packs via `.ai/genres/genres.md`.

## Quick Start

### 1. Initialize a book

> Create a new adult fantasy novel about...

Protocol selection runs **before** book resolution so a sole example book is not mistaken for the active project.

### 2. Write a scene

1. Scene card in `planning/scenes/`
2. Draft → reviews → approval (if configured) → promote → `evt-*` event → fold

### 3. Review

Reviews diagnose; revision is separate. Template: `.ai/templates/review.template.yaml`

## Development Commands

```bash
npm install
npm run validate      # read-only: manifest, schemas, refs, example book
npm test              # fold + validate tests
npm run fold -- .ai/examples/books/memory-echo
npm run fold:check -- .ai/examples/books/memory-echo
```

`validate` and `fold:check` must leave zero persistent file changes.

## V1 Limitations

- Publishing protocols are lightweight placeholders
- No LLM API integration or web UI
- Approval "auth" is honor-system + hash binding (no cryptographic signatures)
- Single-book fold CLI; no cross-book operations
- Full supersession only (no partial field-level patch events)
