# AI Author Orchestration — AGENTS.md

**Repository-driven AI operating system for planning, writing, reviewing, and maintaining long-form fiction.**

This is the root dispatcher. Every AI agent entering this repository must start here.

---

## Mandatory Startup Sequence

Follow this sequence exactly. Do not skip steps. Do not load the entire `.ai/` directory.

1. **Read `AGENTS.md`** (you are here)
2. **Read `.ai/manifest.json`** — machine-readable index of the framework
3. **Read `.ai/rules/rules.md`** — rules dispatcher
4. **Load always-required project and canon rules** (see manifest `mandatory_startup_files`)
5. **Load only additional rules** applicable to the current task
6. **Read `.ai/protocols/protocols.md`** — protocol dispatcher
7. **Select the authoring protocol first** (see Protocol Selection) — distinguish **new-book** vs **existing-book** before resolving a book
8. **Resolve the active book** only when the selected protocol needs an existing workspace (see Book Discovery below). For new-book creation, skip resolution of existing books; initialize first, then resolve the newly created book.
9. **Read `books/<book>/book.yaml`** — book configuration (after the book exists)
10. **Read `.ai/genres/genres.md`** — genre dispatcher
11. **Load only applicable primary/secondary genre packs**
12. **Match relevant skills** via "When to Use" triggers in `.ai/skills/<category>/`
13. **Load only specialist agents** whose roles add value for this task
14. **Read only relevant** canon, planning, state, and manuscript context
15. **Execute the selected protocol**
16. **Perform required reviews**
17. **Obtain human approval when configured** — record durable approval bound to content hash before any canonical persistence
18. **Persist only approved artifacts** (promote drafts → approved paths)
19. **Emit immutable story-state events** for approved narrative changes (never before the approval gate)
20. **Verify before declaring the task complete**

## Source of Truth

| Layer | Location | Responsibility |
|-------|----------|----------------|
| AI operating instructions | `.ai/` | Rules, skills, protocols, agents, templates, schemas |
| Root dispatcher | `AGENTS.md` | Entry point and startup sequence |
| Book identity & config | `books/<book>/book.yaml` | Genre, POV, approval gates, targets |
| Established truth | `books/<book>/canon/` | Approved canonical facts (permanent CANON) |
| Intent | `books/<book>/planning/` | Outlines, scene cards, threads |
| What happened | `books/<book>/state/events/` | Immutable narrative history (event-sourced) |
| Bootstrap state | `books/<book>/state/initial.json` | Optional starting derived inputs |
| Current state | `books/<book>/state/derived/` | Deterministically reconstructed (regenerate, do not hand-edit) |
| Approvals | `books/<book>/approvals/` | Durable human approval records (hash-bound) |
| Prose drafts | `books/<book>/manuscript/drafts/` | Staging; not canonical |
| Approved prose | `books/<book>/manuscript/scenes/` | Promoted after approval |
| Reviews | `books/<book>/reviews/` | Review artifacts |
| Research | `books/<book>/research/` | Factual notes (not fiction canon) |
| Framework examples | `.ai/examples/books/` | Example-only; excluded from active-book resolution |

Harness-specific files (Cursor rules, Claude config, etc.) are **thin adapters** pointing into `.ai/`. They are not canonical.

### Canon vs narrative history vs derived state

| Concern | Authority | Mutability |
|---------|-----------|------------|
| **Canon** | `canon/` via canon-update | Changes only through authorized workflow |
| **Narrative history** | `state/events/` | Immutable; corrections add new events |
| **Derived state** | `state/derived/` | Regenerated by fold; never hand-edited |

Scene approval emits a **state event** and zero or more **canon proposals**. Scene events do **not** establish permanent CANON.

## Book Discovery & Active Book Resolution

**Select the protocol before resolving a book.**

### New-book tasks (`orchestration/initialize-book`)

1. Do **not** resolve an existing active book first.
2. Initialize the workspace under `books/<new-slug>/`.
3. Then resolve the newly created book for subsequent steps.

### Existing-book tasks

1. List directories under `books/` (exclude hidden paths, `books/README.md`, and any example-only trees).
2. **Never** treat `.ai/examples/books/*` as active books.
3. Prefer explicit book slug or title in the user request.
4. Else check environment variable `BOOK_SLUG` if set.
5. If exactly one non-example book exists under `books/`, use it.
6. If multiple books exist and none is specified, **ask the user**.
7. Never mix artifacts from different books in one task.

Skill: `.ai/skills/orchestration/resolve-active-book/SKILL.md`

## Semantic Agent Model

An **agent** is a **role contract**, not a separate process or model.

Examples: `orchestrator`, `prose-writer`, `continuity-editor`

A harness may implement an agent by:

- Spawning a subagent with specialized context
- Switching role instructions in the same session
- Invoking a different model
- Sequential execution in one thread

The semantic contract (Purpose, Allowed, Not Allowed) remains identical across harnesses.

### Delegation

1. Attempt the task directly when no specialization is needed.
2. Load agent from `.ai/agents/<category>/<agent>.md`
3. Respect Allowed / Not Allowed boundaries
4. Use `prepare-agent-brief` skill to package inputs
5. Validate output before integration

## Canon Change Rules

- Established canon cannot change silently.
- Writers may **propose** facts; they may not **establish** canon without authorized workflow.
- On conflict: stop, identify contradiction, propose options, route through `canon-update` protocol.
- Narrative corrections use immutable **correction** events with `supersedes[]` (never mutate old events).
- Canon file status may use `RETCONNED` only via explicit canon-update with human approval when configured.

Rules: `.ai/rules/canon/no-silent-retcon.md`, `.ai/rules/canon/canon-authority.md`

## Story-State Event Handling

Narrative progression is **event-sourced**:

1. Approved scenes produce immutable events in `books/<book>/state/events/` with IDs like `evt-000001` (independent of `scene_id`). Filenames may be descriptive: `evt-000001-scene-0001-approved.json`.
2. Never edit or delete committed events. Corrections add new `event_type: correction` events with `supersedes[]` and full replacement deltas.
3. Optional bootstrap: `books/<book>/state/initial.json`.
4. Regenerate derived state: `npm run fold -- books/<book>`
5. Read-only check: `npm run fold:check -- books/<book>` (must not write `state/derived/`)
6. Use derived state for context loading; use events as historical authority.
7. Invalid events must never fold — validation failures block write.

Do not let multiple agents rewrite shared state JSON files directly.

## Human Approval Gates

Check `books/<book>/book.yaml` → `human_approval` before promoting drafts or emitting canonical state:

- Premise, story bible, macro outline may require approval
- Scenes/chapters when `human_approval.scenes` / `chapters` is true
- Major canon retcons typically require approval
- **Unknown `human_approval` keys must be preserved** and must not be silently treated as `false` if a workflow depends on them — ask the user when unsure

When approval is required:

1. Stage drafts under `manuscript/drafts/` (and review artifacts)
2. Present artifacts and wait for explicit human confirmation
3. Write a durable record under `approvals/` binding `artifact_hash` (sha256)
4. Only then promote to approved paths, emit state events, and fold

If the artifact changes after approval, the approval is **stale** and must be renewed.

Rules: `.ai/rules/artifacts/approvals.md`

## Context Loading Discipline

Before writing or reviewing a scene, load only:

- Scene card
- POV and participant character canon
- Relevant location and world rules
- Current relationship and knowledge state (from derived state)
- Active threads touched by the scene
- Previous scene summary (not full manuscript)
- `narrative-style.md` and applicable genre guidance

Skill: `.ai/skills/orchestration/load-book-context/SKILL.md`

## Completion Verification

Before declaring a task complete:

1. Verify work against loaded rules
2. Run applicable review protocols
3. Ensure artifacts match templates/schemas
4. If `human_approval` requires it: confirm a non-stale approval record exists for the exact artifact hash
5. Only after approval (or when approval is not required): promote draft → approved manuscript path
6. Emit story-state events if narrative history changed
7. Emit canon proposals if permanent CANON may be warranted (do not auto-promote)
8. Run `npm run fold -- books/<book>` if events were added
9. Run `npm run validate` when modifying framework files (validate must not mutate book state)
10. Summarize what was done and what requires human approval

---

## What Is Forbidden

- Loading every `.ai/` file "just in case"
- Treating harness adapter docs as source of truth
- Silent canon retcons or knowledge leakage
- Prose writers changing approved plot outcomes without CHANGE_REQUEST
- Hand-editing `state/derived/` files
- Mutating immutable `state/events/` files
- Emitting state events or promoting manuscripts before a required approval gate
- Establishing permanent CANON directly from scene event `changes`
- Resolving threads or deaths without explicit events
- Loading the full manuscript for routine scene work
- Treating `.ai/examples/books/` as the active book when creating a new book
- Duplicating skill workflows inside protocols or agents
